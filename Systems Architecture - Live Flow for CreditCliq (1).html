    How much each agent may decide

    Every agent has a current level and a ceiling. The ladder stops at A3, so no agent acts alone on money, bureau data or consent.

    A0 WorkerCode only, no model.Credit Monitor, Cost Tracker
    A1 Single callOne structured model call on supplied facts.Recommendation, Policy Reviewer
    A2 Bounded readerPicks allowlisted read tools, at most 5 calls.Guardian, Income Insight, Concierge
    A3 ProposerPrepares one action a person must confirm.Repayment Coach, Concierge
    A4 Unattended actorActs alone on money, bureau data or consent.Not permitted

    Which model handles what

    The cheapest safe option wins, and the small local model is the default whenever text must be generated. The Cost Tracker can only move work toward the cheaper options.

    Cached answerPrepared per subscriber and valid until their facts change.No generation at chat time
    Tier 0: codeScores, dates, counts and lists answered from facts.No model cost
    Tier 1: local CPU LLMIntent, summaries, embeddings, short explanations, quiet-hour batches.Text stays in our environment
    Tier 2: external LLMLong, multi-bureau or step-by-step tasks, and local failures.Facts and redacted question only
    Limit reachedShorter local answer, or an offer to try later.Set by budget and plan

    Starting server settings

    This is a first configuration for the benchmark. Slot count, context and cache size need load testing, and the API key comes from your secrets manager.

    llama-server \
  --model /models/granite-4.1-3b-Q4_K_M.gguf \
  --jinja \
  --parallel 2 \
  --ctx-size 8192 \
  --cache-reuse 256 \
  --cache-ram 2048 \
  --slot-save-path /var/lib/llama/slots/ \
  --metrics \
  --api-key "$LLAMA_API_KEY" \
  --host 127.0.0.1 --port 8080

    Send a json_schema with each request so only the agreed format can come back. The server notes that output may vary with prompt caching on, so test with caching enabled.

    Agent skills and code bases

    Each agent lives in its own folder with a SKILL.md that follows the Agent Skills format: a name matching the folder, a description of what it does and when to use it, and a body under 500 lines with detail in references/. The skill describes behaviour. Permissions are enforced by the policy engine, so a skill file never grants access.

    OAuth for every client
    
      
    Each client signs in with OAuth and gets a short-lived token for one audience. Coding agents start on sandbox data, because anything a tool returns enters the agent's context and may reach its model provider. API keys stay on the REST APIs and are refused at the MCP Server.
